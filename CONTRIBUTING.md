# Contributing

Thank you for your interest in contributing.

## Important

This repository does **not** accept contributions on the default open source model alone.

Contribution terms for this repository are maintained at the **Carrigan Software Solutions LLC GitHub account level** through the company's default community health files and related contribution policies.

All contributions must be submitted under the applicable **Contributor Assignment Agreement** and contribution terms provided by Carrigan Software Solutions LLC. By contributing, you agree that Carrigan Software Solutions LLC will own the contribution and may distribute the contribution under the project's current licensing terms, and may release future versions of the project under different license terms.

If this repository includes a local `CLA.md` or other repository-specific contribution terms, those additional terms also apply to contributions made to this repository.

## How to Contribute

1. Review the applicable contribution and assignment terms provided by Carrigan Software Solutions LLC before doing meaningful work.
2. Review and follow this project's coding standards, conventions, and repository-specific development requirements.
3. Submit changes through a pull request against the appropriate target branch.
4. Include the required assent statement in the pull request body, using your full legal name exactly as requested by the project's contribution process.
5. Do not submit material you do not have the right to contribute.
6. Be prepared to make requested revisions.

## Branching and Versioning

This repository uses a versioned branching model.

- `master` is the forward-development branch for the next unreleased major version and may include breaking changes, major redesigns, and other work intended for a future major release.
- `version/<major>.x` branches are supported release lines for a given major version.
- Smaller features, enhancements, bug fixes, and other non-breaking changes that are appropriate for the current supported release line should generally target the most recent supported `version/<major>.x` branch.
- Breaking changes and major new features should target `master` unless the project maintainers explicitly direct otherwise.
- Older unsupported release lines may be moved to `archive/<major>.x` or otherwise marked as no longer supported at the discretion of the maintainers.

Contributors should choose the target branch carefully. A pull request may be retargeted, declined, or deferred if it is submitted against the wrong branch.

## Pull Request Expectations

- Keep changes focused.
- Include tests when appropriate.
- Update documentation when behavior changes.
- Use clear commit messages.
- Follow the coding standards, style requirements, and project conventions applicable to the repository.
- Target the correct branch for the type of change being proposed.
- Do not submit confidential, proprietary, or third-party material unless you clearly have the right to do so.

## Additional Notes

Carrigan Software Solutions LLC may require a separate manually signed agreement before accepting a contribution.

Submission of a contribution does not create any obligation to merge, publish, credit, or compensate the contributor.
