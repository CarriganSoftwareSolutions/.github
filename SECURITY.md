# Security Policy

## Supported Versions

This project is currently maintained on a rolling basis.

Security fixes, when provided, are generally limited to:

| Version / Branch | Supported |
| --- | --- |
| Latest published release | Yes |
| Current default branch | Best effort |
| Older releases | No |

Carrigan Software Solutions LLC may change support status at any time.

## Reporting a Vulnerability

Please do **not** report security vulnerabilities through public GitHub issues, pull requests, discussions, or other public channels.

Instead, report suspected vulnerabilities privately by using the GitHub **Email us** feature associated with this project or its maintainer profile.

Use a subject line such as:

`Security Vulnerability Report - Carrigan.Core`

## What to Include

To help with investigation, please include as much of the following as possible:

- A clear description of the issue
- The affected package, component, file, or feature
- The version or commit involved
- Steps to reproduce the issue
- Proof-of-concept code, requests, or screenshots, if available
- The potential impact as you understand it
- Any suggested mitigation or fix, if known

## Response Process

Carrigan Software Solutions LLC will make a good-faith effort to:

- Acknowledge receipt of a report within a reasonable time
- Review and validate the report
- Assess impact and remediation options
- Coordinate disclosure as appropriate

Response times may vary depending on severity, complexity, workload, and the quality of the report.

Submission of a report does not guarantee a fix, a response by a specific deadline, or public disclosure.

## Coordinated Disclosure

Please allow a reasonable opportunity to investigate and address reported vulnerabilities before making any public disclosure.

Carrigan Software Solutions LLC reserves the right to determine whether an issue is a security vulnerability, whether a fix will be issued, and when or whether public disclosure will occur.

## Good-Faith Research

Good-faith security research is appreciated. Researchers are expected to:

- Avoid privacy violations, data destruction, service disruption, and social engineering
- Avoid accessing, modifying, or exfiltrating data that does not belong to them
- Avoid actions that would degrade the availability or integrity of systems or services
- Stop testing and report promptly after discovering a potential vulnerability

Activities that are unlawful, disruptive, destructive, or inconsistent with this policy are not authorized.

## Out of Scope

The following are generally out of scope unless they create a demonstrable security impact:

- Issues that require unrealistic or highly impractical preconditions
- Purely theoretical issues without a plausible exploit path
- Best-practice recommendations without a concrete vulnerability
- Vulnerabilities only present in unsupported versions
- Issues caused solely by third-party services outside the control of this project
- Missing headers, version strings, or informational findings that do not create a meaningful security risk by themselves

## No Bounty Program

This project does not currently offer a bug bounty or guaranteed compensation for vulnerability reports.

## Changes

Carrigan Software Solutions LLC may update this Security Policy at any time by revising this file.
